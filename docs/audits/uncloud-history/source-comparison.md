# Source-content comparison

## Scope and reproducibility

Compared supplied `local-sources.json` (8,998 historical blobs: 8,613 Rust, 39 Go, 346 shell) with `upstream-sources.json` (4,605 historical blobs: 4,416 Go, 125 proto, 64 shell). These are blob corpora, not a claim to cover unreachable objects or every language. The main audit records the frozen refs, identifier matches, docs, fixtures and provenance commits.

The accompanying archive contains exact diffs and the analysis manifests. The linked `source-diffs-manifest.json` combines the authoritative baseline, expanded and path-family rows and adds per-row action recommendations, upstream blob IDs and surviving HEAD paths. To reproduce any individual comparison without the original scratch directory:

```sh
git -C /path/to/upstream show <upstream-blob-id> > /tmp/upstream-source
git show <local-blob-id> > /tmp/local-source
diff -u /tmp/upstream-source /tmp/local-source
```

The comparison uses whitespace-normalized whole-file equality, shared stripped lines at least 45 characters long, Rust/Go string literals at least 20 characters long (lowercase, product names normalized), plus full-relative-path and explicit semantic-family matching. Baseline comparisons pin upstream `b7e224a1eff98813b1d1a32034d977be24be994e`.

No normalized whole-file source matches were found. This does **not** prove independent authorship: translations, rearrangements, short snippets and generated data can evade literal comparison. Similarity scores are triage only; common braces and `return err` materially inflate raw Go line ratios. String extraction is intentionally simple and misses escaped/raw multiline strings. Historical paths are represented by aliases; one blob can occur at several paths.

Artifacts: 35 baseline Go diffs (all 23 compose-helper source/test historical blobs, with multiple semantic upstream comparisons for extensions), 2,091 baseline Rust diffs (all historical versions of paths with at least one detected shared literal, mapped to baseline aliases where available), plus 36 nearest-candidate Go diffs and representative Rust diffs. The authoritative counts/aliases are in the manifest. No source or tracker mutations were made.

## Go helper: retain, do not misclassify as copied conversion code

Historical `ployz/compose-helper`, `crates/ployz/compose-helper`, `core/crates/ployz/compose-helper` implementations are structurally different from Uncloud's Go code. Local `main.go` is a versioned stdin/stdout JSON executable loading Compose through compose-go; upstream `pkg/client/compose/project.go` exposes a Go library. Local `convert.go` converts into `object` maps consumed by Rust, whereas upstream `service.go` constructs typed `api.ServiceSpec` and `api.ContainerSpec`. Local extensions support its own publication/storage objects, while upstream conversion returns API volume structures and validates machine names separately.

The historical `convert.go` blobs (full IDs in the manifest) and three `extensions.go` blobs have no shared significant full code line with the strongest upstream `service.go` candidate beyond the compose-go types import. Exact diffs against fixed baseline and nearest historical candidate are provided. Nearest-candidate line ratios are ~15–16% for convert and ~12–13% for extensions; these are boilerplate, not copied-body evidence. Importing the same independently licensed compose-go package is dependency reuse, not importing Uncloud's conversion implementation.

Recommendation: leave the helper in history; its current-tree removal is separately decided by the release cleanup. Do not erase or rewrite these whole files on the current evidence. Retain the possibility of narrower behavioral inspiration; no static comparison can establish clean-room provenance.

Tailcat matches were generic import/error patterns and IP test strings; no positive copied-code finding. Three Go fixture blobs had no >=45-char line candidate and therefore no nearest-match diff; they still participated in whole-file equality scanning.

## Shell and test limitations

Install scripts have the highest shared long-line count (five), but the shared lines are standard systemd settings, package install commands and environment defaults, e.g. `RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX AF_NETLINK`, `curl -fsSL https://get.docker.com | sh`, and installation directory defaults. This is insufficient to label the whole installer copied. Leave the installer on this evidence; identifier wording is separately inventoried.

Rust tests include upstream-compatible example hostnames/Compose syntax, socat behavior, API schema and image-template expression fragments. The scan found no whole-source literal copy. It cannot decide whether translated test scenarios were authored from copied fixtures or an independently written specification. The confirmed verbatim fixture copies override this negative source-code scan for those actual fixture assets. LEAVE rewritten tests unless direct provenance or distinctive copied test prose/data is established; do not treat language translation as automatic clean-room evidence.

All recommendations above are technical provenance triage, not a copyright/license conclusion.

## Explicit matching coverage

the archive’s `basename-candidates.json` records all **7,943** local historical source-blob/upstream-baseline-Go pairs sharing a normalized basename (strip `.rs`/`.go`, lowercase, ignore punctuation; preserve the test suffix). Every pair is tested for shared long lines and string literals, including negatives. Of these, 233 positive candidates get exact diffs. the archive’s `path-coverage.json` separately records **1,011** historical-alias/upstream-baseline pairs sharing the complete relative path after stripping local optional `core/`, `crates/`, `ployz/src/` or `ployzd/src/`, and upstream `internal/machine/`, `internal/`, `pkg/client/`, `pkg/api/` or `cmd/uc|uncloud/`; Rust/Go suffixes are removed. Every such pair receives a diff. Explicit package-specific mappings add corrosion client/subscriptions/store, network endpoint discovery, image/proxy, unregistry daemon startup, compose helper conversion/extensions/loading, hosted DNS and Caddy. The manifest includes **1,374** path/family diffs and **42** matching HEAD comparisons. Main and test files are not equated merely because of their basename; the precise candidate reason remains attached.

All literal-shape candidate paths, including one-literal matches, are included in the refreshed baseline manifest; historical upstream paths missing from baseline are mapped from `cmd/uncloud` to `cmd/uc` or `internal/cli/client` to `pkg/client` where those exist. Paths unavailable at baseline are omitted from baseline diffs but remain in historical candidate output. Manifests include `head_paths` for every blob present at HEAD, so a historical representative path does not conceal a surviving renamed file. Same-path and explicit-family matching is exhaustive **under these stated heuristics**, not an exhaustive proof against translated copying. Lower-content resemblance and translated algorithms outside these mappings remain a methodological limitation.

Final technical disposition: LEAVE compose-go helper, tailcat, generic platform/SQL integration and rewritten tests; REWRITE narrow public-IP policy, socat proxy setup expression, custom DNS wording, and six Corrosion schema versions before cutover; DROP only the independently confirmed disposable copied fixtures/docs where their removal is already planned.
