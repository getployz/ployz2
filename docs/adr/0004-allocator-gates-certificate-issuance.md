# The Allocator gates certificate issuance

Certificate ordering and renewal act only on the Machine whose Allocator view is Held, replacing the rank-staggered timing scheme whose mutual exclusion depended on synchronized clocks and a `RANK_STEP`-covers-`CHALLENGE_WAIT` invariant. A Machine that is not the Allocator steals the row only on replicated evidence of Allocator inaction: due work whose certificate row shows no Allocator attention — a frozen backoff clock, or a passed renewal window no clock ever followed — for longer than a fixed grace, so an alive Allocator keeps the role by advancing the row on every refusal and failed renewal; recording a failure therefore preserves served material rather than skipping material-bearing rows. The stealer then waits out the 5s quiet window before acting, the same liveness tradeoff Machine Subnet assignment already accepts. Per-machine renewal jitter is removed as moot under a single writer. Mixed clusters are safe: a pre-change daemon may still rank-order concurrently, which is at worst the duplicate-order risk the old scheme already carried, and no wire contract changes.
